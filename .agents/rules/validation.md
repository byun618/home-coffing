# 완료 조건

- 작업 결과가 파일·커밋으로 남아 있는가 — 대화에만 있으면 미완이다
- "다 됐다" 선언 전: 실제 실행 결과가 있는가. 추측 기반 판정 금지
- 완료를 화면이 조용해진 것·파일이 생긴 것·exit 0 으로 대신하지 않는다 — 기대한 결과를 직접 확인한다
- 스파이크는 "더 확인해도 알 수 없음"도 유효한 결론 — 공백은 공백으로 명시

- **네이티브 실행 관문** (워커·리뷰어 공통): 사용자의 네이티브 설치 경로에서 최소 1회 실행한 원자료가 있어야 통과로 센다.
  격리 인스턴스·fixture 실행만으로는 세지 않는다 — 격리 실행과 네이티브의 프로세스 정체가 달라 판정이 뒤집힐 수 있다.
  경량 경로여도 1회는 필요하다
<!-- paddock:design D5 -->
  - 네이티브 = API 는 `Dockerfile` 로 빌드한 이미지(`docker build --build-arg APP=api .`, 배포 워크플로와 같은 경로)를 띄워 실제 엔드포인트를 호출,
    앱은 안드로이드 실기기 dev client(`pnpm --filter @home-coffing/app start`)에서 해당 화면 동선을 수행. 운영 배포(`🚀 Deploy API`)·EAS APK 빌드는 사용자만 한다.
  - 격리 실행 = 타입체크·빌드·node 스크립트처럼 실기기·실 API 를 거치지 않는 실행.
<!-- /paddock:design -->
  - 문서·스킬·규칙 일감의 1회는 바뀐 문서가 지시하는 명령·절차를 사용자의 실제 도구·실재료로 수행한 원자료다 —
    바뀐 명령 블록이 있으면 사용자 설치 도구로 그 블록을 실행하고, 없으면 그 일감 맥락이 없는 새 세션이 실재료에 바뀐 문서를 적용해 본다(새 독자 리허설)
- 판정표 형식:

  | 항목 | 기준 | 결과 | 판정(통과/미달/보류) | 근거 | 원장 | 실행 n/총 m |
  | --- | --- | --- | --- | --- | --- | --- |

  - **원장** (H8ⓐ): 예산 원장을 쓰는 관문이면 실행에 쓴 원장 **절대경로**를 적는다. 쓰지 않는 항목은
    `해당 없음 — <이유>` 로 적는다(원장이 없는 프로젝트는 `해당 없음 — 원장 없음`). **빈칸은 무효다** — 원장 환경변수를 비우면 기본 경로로 조용히 풀려
    이미 쓴 예산을 다시 내주는 경로가 열리기 때문에, 생략이 조용히 통과하는 길을 판정표에서 막는다.
  - **실행 n/총 m** (H8ⓑ): 그 항목을 판정하려고 돌린 **모든** 실행 중 통과 회차 n / 총 회차 m.
    재실행이 있었으면 실패 회차의 원자료도 근거에 남긴다. **통과 회차만 적는 것은 무효다** —
    "재실행하면 통과" 가 습관이 되면 그건 관문이 아니다.
    - **수정 라운드가 있으면 라운드를 넘겨 누적해 센다.** 라운드 2 에서 다시 돌린 회차는 라운드 1 의
      회차에 더한다 — 라운드마다 분모를 1 로 되돌리면 "재실행하면 통과" 를 라운드 단위로 하는 셈이다.
    - **분모의 출처는 「명시 실행 목록」 파일 하나다.** 실행 한 번 = 그 파일의 한 행이고, 행에는
      실행 id · 기준 항목 · 명령 · 기대 종료코드 · 실제 종료코드 · 원자료 경로 · 통과/실패를 적는다.
      **요약·인용·산문 주장은 실행이 아니다** — 원자료에 그 회차의 출력이나 종료코드가 있어야 행이 된다.
      근거가 없는 과거 회차는 지우지 않고 `미확정` 으로 적고, 그 항목의 **총 회차는 미확정**으로 보고한다.
      합계는 그 파일의 **칸 값을 세는 것**으로만 만든다 — **원자료를 패턴으로 훑어 회차를 추측하는 집계기를
      쓰지 않는다.** 그런 집계기는 회차를 빠뜨리고 실패를 통과로 센다.
    - **실행이 없는 항목은 `해당 없음 — 문서 검사` 로 적는다.** 문서의 존재·형식·문구만 보는 항목은
      실행 회차가 0 이고, 그것을 `0/0` 이나 `1/1` 로 적으면 둘 다 거짓이다(`0/0` 은 미달로 읽히고
      `1/1` 은 없는 실행을 만든다). **다만 검사 자체를 스크립트로 돌렸다면 그것은 실행이다** —
      실행 회차로 센다. 이 칸도 **빈칸은 무효다.**
  - **경량 경로 예외** (task-coordinate §3): 게이트 ⓪에서 경량으로 확정한 작업은 명시 실행 목록을
    만들지 않고, 원장 칸과 실행 n/총 m 칸에 `해당 없음 — 경량 경로` 를 적는다. 근거 칸의 원자료(네이티브 실행
    1회 포함)는 그대로 필요하고, **실패한 회차의 원자료도 지우지 않는다** — 원장을 안 쓴다고 실패를 숨겨도 되는 것은 아니다.
    전체 경로 작업에 이 문구를 쓰면 빈칸과 같이 무효다.
- 완료는 『완료 감지』로 본다 — 그 능력이 공백인 도구에서는 완료 칸이 공백이고 판정은 `보류` 다 (`.agents/harness/capabilities.md`)

## 원자료 보관

- 원자료는 산출물 레포(`<본체>/../home-coffing-specs/`)에만 둔다 — 코드 레포에는 커밋하지 않는다. 아래 「커밋한다」는 산출물 레포 커밋이다.
- **커밋한다**: 판정표·`reviews.md`·실행 목록이 가리키는 회차의 원자료. 실패 회차는 위 규칙대로 전부.
- **커밋하지 않는다**:
  - 사용자 데이터 사본(이 프로젝트의 목록은 아래). 작업 폴더 밖(`/tmp` 등)에 두고 경로·해시만 기록한다.
    원복 해시 대조가 통과하고 사용자 확인이 끝나면 지운다 — 작업이 끝날 때.
<!-- paddock:design D6 -->
    - homelab 호스트 MySQL(스키마 `home_coffing`)은 공유 자원 — 새로 띄우지 않는다. `schema:update`·`schema:drop`·`db:reset` 은 사용자 승인 없이
      실행하지 않는다(파괴적, 운영과 같은 서버). 로컬 `.env` 가 운영 스키마를 가리키는지는 확인 필요 — 확인 전엔 운영으로 간주한다
    - 한 번에 하나만: DB 스키마 변경, 실기기 dev client(Metro 8081), 로컬 API 포트(3001)
    - 커밋하지 않는다: 루트 `.env`·`apps/app/.env`(시크릿), `backups/`(DB 덤프), DB 덤프·조회 결과 사본
<!-- /paddock:design -->
  - 재생 가능한 산출물(빌드 결과·의존성 폴더·설치본 사본).
  - 판정 회차가 아닌 구현 중 반복 실행(고치며 다시 돌린 측정 등). 원인 증명·양성 대조로 인용되면 판정 회차다. **애매하면 커밋한다.**
- **시크릿**: 환경변수 덤프(`env`·`printenv` 등)는 키 이름만 남기거나 값을 가린다.
- **크기 경보**: 파일 하나 5MB 초과 또는 작업 원자료 합계 50MB 초과면 커밋 전에 `verdict.md` 에 사유 한 줄. 막지는 않는다.
