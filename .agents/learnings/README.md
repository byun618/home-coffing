# learnings — 아직 규칙이 되지 않은 배움

규칙·스킬·테스트·ADR 로 박을 만큼 검증되지 않았지만 다시 쓸 만한 배움을 담는 **임시 수신함**이다.
영구 명세도, 매 작업에 자동으로 싣는 문맥도 아니다. 형식·상한·읽기·압축·승격의 원본은 이 파일 한 곳이다
(방식 출처: VS Code `.github/learnings` + `feedback-learning` 스킬).

- 영역 파일 `.agents/learnings/<영역>.md` 는 첫 항목이 생길 때 만든다. 영역 목록을 미리 두지 않는다.
- 언제 제안하고 어디서 채택하는지는 그 절차를 실행하는 스킬이 정한다. 그런 스킬이 없으면 배움을 겪은 세션이 쓰고, 커밋 전에 사용자 확인을 받는다.
- 제안 = task-coordinate §8 게이트 ②.

## 어디에 둘까 — 목적지 분류

배움 하나를 쓰기 전에 가장 작은 권위 있는 자리를 고른다. learnings 는 그중 하나일 뿐이다.

| 배움의 종류 | 목적지 |
| --- | --- |
| 그 작업에만 맞는 선호·일회성 조정 | 저장하지 않는다 |
| 다시 깨지면 안 되는 구체적 동작 | 회귀 테스트 |
| 오래 갈 구조·제품 불변식 | ADR (`docs/adr/`) |
| 레포 전체 규칙 | `.agents/rules/` |
| 다시 쓸 만하지만 덜 검증된 지침 | learnings (`.agents/learnings/<영역>.md`) |
| 도구가 이끄는 절차 | 그 스킬 (`.agents/skills/<이름>/SKILL.md`) |

- **같은 실수 첫 번째 = learnings, 두 번째 = rules 승격** (AGENTS.md 「원본 관리」의 rules 스텁 줄과 같은 사다리).
- 쓰기 전에 rules·스킬·테스트·ADR·기존 learnings 를 먼저 찾는다. 이미 있으면 새로 쓰지 않고 그것을 고친다.

## 형식

```markdown
# <영역> learnings

Last reviewed: YYYY-MM-DD

## <짧은 주제>

- **Scope:** `<영향 경로/**>` 또는 단계 이름
- **Learning:** 일반화한 원칙 1~2문장.
- **Evidence:** 이번 일감 너머로 다시 쓸 만한 이유. 근거는 일감 번호로만 가리킨다.
- **Disposition:** 승격 후보 위치 (`<rules·스킬·테스트·ADR 중 어디>`).
```

- **일반화**: 사건 연대기를 쓰지 않는다 — 원칙만 남긴다. 임시 심볼 이름·줄 번호·구현 세부는 그것이 계약일 때만.
  한 번 기각된 구현 하나를 보편 금지로 만들지 않는다.
- **공개될 수 있는 레포라면**: 홈 경로·사용자 이름·작업 원자료 경로·세션 id·사용자 원문 인용을 넣지 않는다 (`docs/adr/` 도 이 줄을 따른다).

## 상한과 압축

- **영역 파일 하나에 주제 10개·8KB(파일 바이트, `wc -c` — 한글은 글자당 3바이트) 까지.** 새 항목이 둘 중 하나라도 넘기면 기존 항목을 승격·병합·삭제한 뒤에야
  새 배움을 남길지 정한다.
- **쓰기 전에 매번 압축한다**: 겹치는 항목은 하나의 원칙으로 합치고, 낡거나 반박됐거나 이미 승격됐거나 근거가 약한 항목은 지운다.
- **90일 재검토는 파일 단위다** — `Last reviewed` 가 90일을 넘었거나 상한에 닿은 파일은 전체를 검토하고, 남긴 항목을 지금 코드·규칙과
  대조한 뒤 날짜를 갱신한다. 재검토 자리는 회고 절차가 정한다 — 그런 절차가 없으면 사용자가 요청할 때 한다. 작업 중에 낡은 파일을 보면 고치지 않고 알린다.
- 영역 파일은 0개 항목까지 줄어도 된다. 「언젠가 쓸모 있을지 몰라서」 남기지 않는다.

## 승격

- **승격하면 같은 변경에서 learnings 항목을 지운다.** 같은 규칙을 learnings·rules·스킬·ADR 두 곳 이상에 복사하지 않는다.
- 승격 제안에는 두 가지를 붙인다:
  - **안 통하는 자리 세기** — 그 규칙을 박았을 때 맞지 않는 단계·도구·경로를 센다.
  - **시나리오 열거** — 그 규칙이 막았을 사례와 잘못 막을 사례를 하나 이상씩 적는다.

## 읽기

- **모든 작업에 주입하지 않는다.** 제목과 `Scope` 를 먼저 훑고 맞는 항목만 읽는다.
- learnings 는 코드·테스트·rules·스킬·ADR 보다 권위가 낮다. 어긋나면 그쪽이 맞고, 그 항목은 다음 압축 때 지운다.
