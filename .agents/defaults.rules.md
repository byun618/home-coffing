# 역할 기본값 규칙

역할별 도구·모델·effort 의 **값**은 [`defaults.md`](defaults.md)(프로젝트 소유)에 있고, 이 파일은 그 값을 쓰는 **규칙**이다(paddock 고정).
**도구가 자동으로 읽는 파일이 아니다** — 각 스킬·역할 파일이 이 경로로 가리켜야 읽힌다.
역할 이름: 「지정 리뷰어」= `defaults.md` 의 코드 리뷰 ①, 「대체 리뷰어」= 코드 리뷰 ② 이하, 「외부 서치 도구」= 분석 단계 외부 서치를 맡은 도구.

## 운영 규칙

- **effort·모델은 기동 시 반드시 명시한다.** 환경 기본이 낮을 수 있어 플래그가 없으면 조용히
  내려간다. 기동 후 세션 중간에 바꾸지 않는다 — 프롬프트 캐시가 깨져 입력 비용이 수십 배로 뛴다.
- **다른 도구에 위임하는 워커도 모델·effort 를 킥오프에 명시한다.** 위임 경로는 지정이 없으면 모델·effort 를
  넘기지 않고 세션 기본을 탄다 — "맡겼으니 지정한 모델일 것"은 성립하지 않는다.
- 모델은 전체 식별자로 요청한다. 전체 식별자는 고정 스냅샷이라 같은 계열의 새 버전으로 올라가지 않는다.
  별칭은 제공자별 권장 버전으로 바뀌어 버전 고정이 아니다 — 새 모델이 나오면 `defaults.md` 의 식별자를 직접 올린다.
  시작 시 요청한 식별자와 실제 해석된 모델을 구분해 기록한다. 확인 불가를 성공으로 쓰지 않는다.
- advisor 는 기본 해제다. 켜는 것은 명시 변경으로만 하고, 별도 effort·호출 횟수 옵션을 가정하지 않는다.
  **advisor 는 독립 리뷰어가 아니다** — 조언 자체는 지적이 아니며 지적은 diff 에서 재현 가능해야 등록한다.
- 시작 시 전체 역할·모델·effort·구현 방식·명시 변경을 `00-start.md` 에 복사한다.
  `02-kickoff.md` 는 그 기록을 따른다. 재개는 저장된 구성을 유지하고 새 기본값을 소급하지 않는다.
- 모델 미지원·사용량 소진 시 대체 모델을 임의 기동하지 않는다. 해당 단계와 가능한 대안을 보고한다.
  사전 승인된 예외는 「리뷰어 사용 불가 시 자동 전환」의 리뷰어 전환(대상은 `defaults.md` 의 대체 리뷰어뿐)과 「외부 서치 한도 소진 시 생략」 둘이다.
- 사용자 승인 게이트 3단(킥오프·채택·PR 생성 — AGENTS.md 「작업 플로우」)을 유지한다.

## 리뷰어 구성 변경 기록

리뷰어 일부를 중지하거나(사용자 지시) 자동 전환으로 구성이 줄었을 때의 규칙이다.

- 신규 작업은 `00-start.md` 역할 구성에 중지된 리뷰어를 `일시 중지` 로 기록한다. 재리뷰도 같은 구성이다.
- 판정문(`verdict.md`)에 줄어든 구성과 시점·사유를 적는다 — 리뷰어가 줄었다는 사실이 판정 근거에 드러나야 한다.
- 리뷰어가 하나라도 원칙은 그대로다: 전원 침묵(= 그 리뷰어의 침묵)을 통과 근거로 쓰지 않는다. 게이트 ① 사용자 확인의 비중이 커진다.
- 중지한 구성의 재개는 사용자 지시로만 한다. 재개할 때 `defaults.md` 의 중지 표시를 지운다.
- 분석 단계의 **외부 서치**(AGENTS.md 플로우 1)는 코드 리뷰가 아니므로 이 중지 대상이 아니다.
- 재개 중인 기존 작업은 기록된 구성을 유지한다 — 단, 사용자가 그 작업에도 적용하라고 하면 따른다.

## 리뷰어 사용 불가 시 자동 전환

리뷰 라운드마다 지정 리뷰어를 띄우기 직전에 쓸 수 있는지 확인하고, 쓸 수 없으면 그 라운드를
**대체 리뷰어 구성**으로 자동 전환한다. 위 「리뷰어 구성 변경 기록」의 일시 중지에 대한 예외이며 사용자 재승인은 필요 없다.

- **조건 둘** — 하나라도 맞으면 「사용 불가」다:
  ① 지정 모델(`defaults.md` 의 식별자)이 **계정 카탈로그**(그 도구가 이 계정에 실제로 내주는 모델 목록)에 없다
  ② 사용량 — 한도 창 중 하나라도 사용률 ≥ 90%.
- **확인 순서: 카탈로그 먼저.** 부재면 사용량을 보지 않고 바로 전환한다 — 사용량은 지정 모델이 계정에 있는지
  알려 주지 않아서, 사용량이 낮아도 부재는 거르지 못한다.
- **카탈로그 확인**: 서버에서 갱신한 **계정 카탈로그**를 쓴다. 도구·패키지에 내장된 목록은 계정이 못 쓰는 모델도 들어 있어
  부재 판정에 쓰지 않는다. 확인 명령은 도구마다 다르다 — 선택한 매핑을 따르고, 명령이 없거나 출력이 비면 확인 실패다.
  슬러그는 지정 식별자와 **정확히 같은 줄**로 대조한다. 숨김 표시여도 목록에 있으면 「있음」이다.
  **갱신 실패 시 내장 목록으로 조용히 떨어질 수 있다** — 그래서 「있음」은 띄워도 된다는 보장이 아니다. 거절은 아래 기동 확인에서 잡는다.
  판정에 쓴 목록 원문은 그 라운드 `reviews.md` 절에 붙인다.
- **사용량 확인**: 도구가 남긴 세션 기록에서 사용량이 든 **가장 최근** 기록의 마지막 값을 읽는다. 최신 파일 하나만 보면 안 된다 —
  거절된 세션·빈 세션은 사용량을 남기지 않아서 그것이 최신이면 빈 출력이 된다. 최근 몇십 개 안에 없으면 확인 실패다. 읽은 파일 경로도 같이 적는다.
  등급과 창마다 사용률·창 길이·초기화 시각을 **그대로 적는다** — 창이 둘이면(예: 단기 + 주간) 두 창 모두 적는다.
  **초기화 시각이 확인 시각보다 지났으면** 그 값은 지난 창의 것이다 — 그 창은 사용 불가로 세지 않고 「확인 실패」와 같이 다루며, 대조 결과를 적는다.
  창 길이는 등급마다 다르다. 값은 **마지막 호출 시점**의 서버 응답이라 그 뒤 다른 기기 사용분은 빠져 있다. 공식 조회 API 가 아니다.
- **임계값 90%**: 기록 값이 실제보다 낮을 수 있어서 여유를 둔다.
- **확인 실패는 사용 불가가 아니다**: 카탈로그·기록을 못 읽거나 형식이 달라 판단할 수 없는 조건은 사용 불가로 세지 않는다 —
  판단한 다른 조건도 사용 불가가 아니면 지정 리뷰어를 그대로 띄운다.
  띄운 지정 리뷰어는(확인 실패로 띄웠든 「있음」으로 띄웠든) **완료 보고에 기대지 않고** 기동 단계에서 확인한다:
  - **거절 확인** — 『본문 주입』이 확정되면 **곧바로(수 초 안) 『화면 관측』을 한 번** 한다. 거절(모델 없음·한도 초과 등)은
    첫 턴 제출 뒤 수 초 안에 화면에 뜨고 도구는 입력 대기로 돌아간다 — 모델이 돌지 않으니 완료 보고를 기다리지 않는다.
    보이면 그 시도를 『회수·정리』로 끝내고 그 라운드를 대체 구성으로 다시 띄운다.
    거절이 안 보이는 것만으로는 너무 일찍 본 것과 구별되지 않는다 — 화면의 응답 진행 또는 첫 heartbeat 로 정상 진행을 확인한다.
  - **주입 미확정** — 『준비 대기』·『본문 주입』이 확정되지 않는 것은 **모델 부재의 신호가 아니다** — 카탈로그에 있는 모델도 같은 경로에서 똑같이 멈출 수 있다.
    재개는 선택한 매핑의 『감독 워커 기동』 복구 조건을 따른다 — 화면을 먼저 읽고, 재개로 수렴하지 않는 상태면 재개하지 않는다.
    재개 뒤 거절이 보이면 위대로, 재개하지 않았거나 여전히 미확정이면 그 시도를 『회수·정리』로 끝내고 대체 구성으로 다시 띄운다.
- **대체 리뷰어도 실패하면 남은 리뷰어로 진행한다** (멈추거나 리뷰를 건너뛰는 것보다 낫다).
  대체 구성에는 구현자와 다른 모델의 리뷰어를 하나 이상 둔다 — `defaults.md` 가 그렇게 지정한다.
- **전환 대상은 `defaults.md` 에 대체 리뷰어로 적힌 구성뿐이다.** 지정 도구의 다른 모델(무료 등급 모델 등)로 바꿔 띄우지 않는다 —
  지정 리뷰어의 선택 근거(`defaults.md` 「선택 근거」)가 그 모델에는 없다.
- **경쟁 구현의 지정 도구 측**: 같은 카탈로그·사용량 확인에서 사용 불가면 경쟁을 **불가로 보고**한다. 다른 모델로 대체하지 않는다.
- **복귀**: 라운드마다 다시 판단한다. 지정 모델이 카탈로그에 돌아오고 사용률이 90% 아래면 다음 라운드부터 지정 리뷰어로 돌아간다.
- **기록·보고**: 전환한 라운드마다 전환 사유(모델 부재 / 사용량 — 사용량이면 읽은 파일 경로·등급·창마다 사용률·창 길이·초기화 시각 /
  기동 확인 — 거절 / 주입 미확정, 원인을 가리지 못하면 그렇게 적는다)·
  관측 시각·실제 리뷰 구성을 그 라운드의 `reviews.md` 절을 쓸 때 적고, `verdict.md` 라운드 요약표에 옮기고, 사용자에게 한 줄로 알린다. 조용한 전환이 아니다.

## 외부 서치 한도 소진 시 생략

분석 단계(AGENTS.md 플로우 1)의 외부 서치는 외부 서치 도구의 한도가 소진됐으면 **생략하고 코디 검색만으로 진행한다.**
「외부 서치 도구가 없으면 차단 사유로 보고」(task-coordinate §0)의 예외이며 사용자 재승인은 필요 없다.
한도 확인은 task-coordinate §1-2 에서 외부 서치를 띄우기로 판단한 경우에만 한다 — 조건 미해당 생략은 그 절의 기록 방식을 따른다.

- **확인 방법**: 한도를 보여 주는 화면(기동 배너 등)을 『화면 관측』으로 읽고, **입력 없이** 닫는다. 인증 상태 조회는 한도를 주지 않을 수 있다.
  확인 수단은 도구마다 다르다 — 선택한 매핑을 따른다.
- **0% 면 생략**한다. 한도를 못 읽거나 형식이 다르면 소진으로 보지 않고 평소대로 서치를 맡긴다. 서치 도중 한도 초과로
  끝나면 그때까지 받은 답만 쓰고 나머지는 생략으로 기록한다.
- **대체**: 코디 웹 검색에 더해 `gh` 로 대상 저장소 이슈·PR 을 직접 찾는다(외부 서치가 주로 메우던 이슈 트래커·버전 변화 쪽).
  다른 도구로 외부 서치 역할을 흉내 내지 않는다 — 대조가 빠진 것은 빠진 대로 둔다.
- **기록·보고**: `00-analysis.md` 서치 표에 「외부 서치 미기동 — 한도 0%(관측 시각)」를 적고, 교차 대조 칸은 **공백**으로 둔다.
  게이트 ⓪ 보고에 한 줄로 알린다. 코드 리뷰 쪽 외부 서치 도구 실패 처리는 위 「리뷰어 사용 불가 시 자동 전환」을 따른다.

## 경쟁 구현

옵션이다.

- 기본은 단독이다. 코디네이터 추천 또는 사용자 요구로 발동하며 **발동 근거를 킥오프에 명시한다**:
  ① 접근이 갈리고 문서로 우열이 안 날 때 ② 되돌리기 비싼 변경 ③ 주 구현 도구의 주간 쿼터가 임계에 근접했을 때
- 경쟁 페어 구성은 `defaults.md` 「역할 기본값」의 경쟁 행이다. 상대 측을 쓸 수 없으면
  「리뷰어 사용 불가 시 자동 전환」의 경쟁 구현 줄대로 경쟁 불가로 보고한다. 명시한 구현자 모델이
  있으면 그 지정이 우선한다. 주 구현 도구 쪽 워커 수는 단독일 때와 같으므로 경쟁이 그 쿼터를 늘리지 않는다.
- 각 후보는 같은 킥오프·같은 기준을 받고 독립 구현한다. 상대 구현·리뷰·판정을 공유하지 않는다.
- 자기 구현 브랜치에 대한 리뷰는 지적 수집에는 쓰되 **승자 판정 근거로 세지 않는다.**
