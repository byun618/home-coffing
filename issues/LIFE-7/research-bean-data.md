## 4. 등급 시스템 (G1/G2/AA/SHB/NY2 등)

원산지별로 *기준이 다름*. catalog selector로 쓸 거면 *enum 단일이 아니라 origin별 set*.

### 에티오피아 — 결점두 수 (300g당)

| 등급 | 결점두 | 비고 |
|---|---|---|
| G1 | ≤ 3개 + 컵스코어 80+ | 스페셜티 최고급. 게이샤·아바야·코케허니 등 |
| G2 | 4~12개 | 수출 등급. 일반 스페셜티 |
| G3 | 13~25개 | (드물게 유통) |
| G4 | 26~45개 | 중급. 가성비 라인 |
| G5+ | 46+ | 일반 상업 |

> *G2가 G1보다 결점은 많으나 크기 등 다른 기준으로 더 클 수도* (사이즈 vs 결점 trade-off).

### 케냐 — bean size (스크린)

| 등급 | 의미 |
|---|---|
| AA | 매우 큰 콩 (스크린 17-18) — 밝은 산미·복합 |
| AB | A + B (스크린 15-16) — 중간 |
| PB | 피베리 — 라운드 |
| C / TT / T | 작거나 결함 |

### 중미 (과테말라·콜롬비아·코스타리카) — 고도

| 등급 | 의미 |
|---|---|
| SHB / SHG | Strictly Hard Bean / Grown — 1300m+ |
| HB / HG | Hard Bean — 1200-1300m |
| 수프리모 (콜롬비아) | 스크린 17+ 대형 |
| 엑셀소 (콜롬비아) | 스크린 14-16 |

### 브라질 — NY (결점) + 스크린

| 등급 | 의미 |
|---|---|
| NY2 | 결점 ≤ 4 (최상급 수출) |
| NY3 | 결점 4-8 |
| NY4 | 결점 12 |

### 결론: 등급 = origin-coupled

등급은 *국가별로 의미가 다른 enum*. catalog 단일 enum X. **상품명에 포함되어 있어** 자체 검색·표시는 됨. 별도 `grade` 필드는 *redundant*. 빼는 게 맞음.

## 5. 필드별 cardinality·catalog성 평가

| 필드 | 원두반점 라벨 출현률 | cardinality | catalog성 | 005 권장 |
|---|---|---|---|---|
| **name (상품명)** | 100% | 무한 (자유 텍스트) | text | ✅ 필수, unique 식별 |
| **type** (싱글/블렌드/디카페인) | 카테고리로 100% | 3 (또는 4 — 한정포함) | enum 작음 | ✅ 추가 권장 |
| **process** (가공) | ~30% (일부만 명시) | 4-5 enum | enum | ⚠ optional |
| **roastery** | 100% (단일 사이트 가정) | 적음 | enum / text | OOS (005에서 안 다룸) |
| **origin (국가)** | 100% (이름에 포함) | ~30개 | enum 가능 but 이름과 중복 | ❌ 빼기 |
| **origin (지역/농장)** | 70% (이름에 포함) | 수백 | text/long-tail | ❌ 빼기 (이름에 포함) |
| **variety** (게이샤·SL28 등) | 30% (이름에 포함 시만) | 20-30 enum | enum | ❌ 빼기 (이름에 포함) |

| **tastingNote** (#tag) | 60% (한 줄짜리 해시태그) | 단어 풀 ~50 | tag list | ⚠ optional, 추후 검색 활용 |
| **altitude** | <5% | 자유 텍스트 | text | ❌ 빼기 |
| **harvest** | <5% | 자유 텍스트 | text | ❌ 빼기 |

## 6. 외부 catalog DB

조사 시점 한국 catalog DB *없음* (확인된 한). 글로벌로는 SCA·WCR이 *품종·가공 표준*만 정의. 가격·라벨 DB 공개 안 함.

→ catalog seed는 *원두반점 product list 직접 큐레이션*이 현실적.

## 7. 핵심 Insight

1. **단일 로스터리 가정 시 roastery 필드 불필요** — 본인+와이프가 원두반점 위주로 사면 식별·검색에 무의미. → 005 OOS 결정 fit.

2. **상품명 1개 필드에 식별 정보 다 들어있음** — 국가·지역·농장·품종·가공·등급이 모두 상품명에 *자연스럽게* 표현됨. → origin·variety·grade 별도 필드 분리는 *redundant*.

3. **가공방식이 라벨에 일관 안 나옴** — 원두반점 기준 ~30%만 명시. 강제 enum X, optional.

4. **상품 universe가 30-40종으로 작음** — 본인이 *전부 미리 catalog seed*하면 hit율 거의 100%. 사용자 register 부담 사실상 0.

5. **type (블렌드/싱글/디카페인) + tastingNote (#태그)가 가장 활용도 높은 추가 메타** — catalog 분류·검색의 기본.

6. **등급 시스템은 origin별로 다른 의미** — G1(에티오피아) ↔ AA(케냐) ↔ SHB(중미) ↔ NY2(브라질). 단일 enum 불가. 별도 grade 필드 만들지 말고 *상품명에 포함된 그대로*.

7. **메타 정보(원산지·고도·품종·가공·tastingNote)는 *이미지(라벨/상품 페이지)에서 자동 추출*하는 게 정확·편의성 둘 다 우월** — 사용자가 입력하는 것보다. *진짜 register 폼*은 OCR/Vision 기반이 정답. 후속 ticket 가치 높음.
